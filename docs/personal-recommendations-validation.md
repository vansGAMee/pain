# Проверка режима «Весь мой вкус», 29 октября 2026

Режим добавлен отдельно; прежние режимы не заменяются. Проверки читали изолированную копию пользовательской библиотеки. Проверки не записывали исходные файлы библиотеки, истории и анализа. JSON, относящиеся к копии, сверены до и после выполнения: совпадают.

## Выбор метода

В снимке 773 трека, 5002 записи истории, 56 действующих лайков, 773 готовых CLAP-вектора и подробные акустические профили. Для обучения доступны 4790 окончательных исходов; остальные записи не трактуются как окончательные предпочтения. Сети для совместной фильтрации не выбраны: одной локальной истории недостаточно для полноценного пользовательско-предметного графа LightGCN/ALS.

Использованы опубликованные компоненты:

- [CLAP, официальный репозиторий](https://github.com/LAION-AI/CLAP): существующие 512-мерные эмбеддинги реального аудио; нейросеть заново не обучается.
- [RandomForestRegressor](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.RandomForestRegressor.html): CART на bootstrap-выборках, 100 деревьев из стандартной конфигурации; один поток CPU, стандартное случайное подмножество признаков sqrt. Размер листа и включение времени проверяются на более поздних событиях, без ручных музыкальных коэффициентов.
- [Bootstrapped Thompson Sampling, рабочая реализация contextualbandits](https://github.com/david-cortes/contextualbandits/blob/master/contextualbandits/online.py): эмпирическое распределение выбора через bootstrap-модели. Конечное число голосов сглаживается стандартным Dirichlet(1)/Laplace, чтобы отсутствие побед в ансамбле не означало невозможность выбора.
- [Лапласовское сглаживание вероятностей](https://nlp.stanford.edu/IR-book/html/htmledition/naive-bayes-text-classification-1.html): частотная основа — реальные дослушивания, один действующий лайк и единичный стандартный prior.
- [Байесовская смесь последовательных экспертов](https://www.cs.cmu.edu/~aarti/Class/10704_Fall16/lec15.pdf): исходный частотный вариант и обученный вариант, равномерный prior по двум экспертам, обновление по вероятности фактически наблюдённого исхода. Для немедленной обратной связи существует оценка накопленной log-loss через log(2). В плеере исходы задержаны, поэтому эта теорема **не заявляется как гарантия живого качества**.
- Для объяснения конкретной обученной оценки — [разложение пути дерева Saabas/treeinterpreter](https://github.com/andosa/treeinterpreter). Сумма вкладов и базового значения проверяется против настоящего `forest.predict`; это описание модели до смешивания, не причинное объяснение вкуса человека.
- Для явно закреплённого вайба — обычное гауссовское условное правдоподобие, диагональная выборочная ковариация и [ширина Scott](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.gaussian_kde.html). В свободном подборе предыдущая песня не задаёт звуковой ориентир.

К обучению подаются CLAP, измеренные спектр, изменчивость, MFCC и спектральный контраст, собственные предыдущие наблюдения трека и контекст. Часы представлены sin/cos с периодом суток; предпочтения по времени учатся из событий, а не из списка жанров по часам. Численный прогноз доли прослушивания не выдаётся в интерфейсе за достоверную вероятность.

## Что проверено на реальных данных

События упорядочены по началу. Для признаков учитываются только исходы, уже доступные в тот момент: конец прослушанного времени, сохранённая отметка исхода и конец временных срезов. Пересекающиеся события не передают результат из будущего. Отдельные проверки покрывают паузы, перемотки, повторное сохранение и ретрансляцию событий.

3832 исхода использованы для обучения и выбора структуры, последующие 958 — для воспроизведения проверки. Лайки скрыты в историческом сравнении: времени их постановки в данных нет. Каталог фиксирован; исторические моменты появления файлов и доставки синхронизации неизвестны.

**Ограничение проверки:** этот поздний период сначала выявил провал свободного ранжирования и затем использовался при разработке безопасного сочетания. Финальный повтор не называется независимым нетронутым тестом. Это воспроизводимая диагностика на одном пользователе, не доказательство универсального превосходства.

| Метрика | Частотная основа | Итоговая проверка |
|---|---:|---:|
| Следующий дослушанный трек, Recall@10 | 30,77% | 31,54% |
| Следующий дослушанный трек, Recall@50 | 54,62% | 54,62% |
| NDCG@50 внутри частотного порядка | 0,22917 | 0,22930 |
| Log-loss фактической вероятностной политики, меньше лучше | 5,21364 | 5,21897 |
| AUC разделения дослушиваний среди реально включённых треков | 0,71401 | 0,94074 |

AUC не означает «94% рекомендаций понравятся». Выделение дослушиваний и угадывание следующего выбранного трека — разные задачи. Численный прогноз доли прослушивания улучшил MSE относительно прежнего среднего по треку: 0,12377 против 0,14976. Однако это не даёт преимущества по всем метрикам выбора следующей песни; модель не используется как самостоятельная основная система.

Именно поэтому частотная основа сохранена в вероятности каждой частотной группы. На этом воспроизведении байесовская смесь практически полностью переключилась на частотный вариант: доля обученного эксперта после 130 доступных дослушиваний — 3,69 × 10⁻¹². Этот результат не скрывается: вероятностный выбор обученного эксперта на данном периоде проиграл, и защита выбрала baseline. Значение не прошито в код: на новой истории оно обновляется по новым исходам. До обновлений защиты, на начальном prior, 100 шеститрековых выборок дали 295 разных треков; это проверка вариативности, не качества и не разнообразия после всех 130 обновлений. Фиксированной квоты новых песен нет.

Для звуковой проверки рассмотрены реальные phonk-записи и электронная музыка из снимка. Например, у Scary Garry косинусное сходство с Live Another Day — 0,705, с End of Line — 0,316; у RAVE соответственно 0,678 и 0,649. Это проверяет конкретный пример разделения по звуку, **не гарантирует жанровую классификацию всей библиотеки**. Производственный код не содержит этих названий и не делит жанры по одному басовому показателю.

Дополнительно сформированы четыре настоящие шеститрековые подборки с действующими лайками: две свободные и две с явно закреплённым звуковым вайбом. Проверены получившиеся названия и исполнители, фактическое применение вайба и вариативность. Свободные подборки охватывают разные направления из истории и могут заметно менять стиль; это не обещание непрерывности одного жанра. Вайб направляет звук, но не является подтверждённым жанровым фильтром. Проверка нескольких очередей не заменяет длительную оценку самим слушателем.

## Производительность и интерфейс

Первое обучение в повторе проверки — около 12,3 с вне интерфейсного потока; при параллельной интеграционной нагрузке — около 15,2 с. Плеер его не ждёт: первый холодный ответ в настоящей браузерной проверке получен за 715 мс, и музыка продолжилась через частотный вариант. Во время обучения и обновлений используется тот же fallback. Готовая модель обновляет предварительный подбор, сохраняя порядок уже выбранной пользователем подборки. Полное вычисление bootstrap-оценок для 773 треков: медиана 31,2 мс, 95-й процентиль 34,2 мс на CPU. Декодирования файлов и запуска Torch при подборе нет. На больших библиотеках эти времена не гарантируются; накопление задач ограничено, обучение выполняется одним потоком CPU.

Дополнительно в отдельную временную копию внесены настоящие более поздние события из продолжающего работать плеера. Модель обновилась с 4790 до 4867 окончательных исходов: повторное обучение выбранной структуры — 3721 мс, следующий кешированный запрос — 13 мс. Запрос обновления немедленно вернул готовность частотного fallback. Исходная история только читалась. Этот тест проверяет обновление и скорость, а не обещает рост субъективного качества.

В настоящем браузерном воспроизведении проверены выбор режима, переход на реальный трек, сохранённое объяснение, сохранение 512-мерного отпечатка вайба, продолжение музыки при сохранении и восстановление после перезагрузки. Отдельная проверка учёта: три отправки промежуточного/окончательного состояния дали один ID, одно сохранённое прослушивание и значение «1» в фонотеке.

Промежуточный checkpoint даже после 90% уникального покрытия не становится окончательным дослушиванием: флаг завершения выставляется при закрытии события. Это отдельно проверено, вместе с сохранением ID и невозможностью закрыть одно событие дважды.

В исходной истории также найдены шесть противоречий между флагом дослушивания и уникальным покрытием ниже действующего порога 90%. Исторические флаги не переписаны; это дополнительный источник шума метрики. Для будущих записей Android применяет уже существующее правило `ListeningMath.completed`, включая случай перемотки к концу.

Исходные спорные пересечения истории не удалялись. Подтверждённые связи идентичности сохраняются отдельно; похожие временные отметки без доказательств не сливаются.

## Повторение

Сначала создайте отдельную приватную копию `library.json`, `stats.json`, `dj-state.json` и `pulseflow/catalog.npz`, сохранив структуру каталогов. Скрипт отказывается работать с живым `desktop/data`. Внешние ссылки на аудиофайлы нужны только для проверки свежести отпечатков и чтения аудио в браузерном тесте.

```bash
desktop/.pulseflow-venv/bin/python desktop/test/evaluate-personal.py \
  --data /path/to/private-copy --output /tmp/pain-personal-audit.json

desktop/.pulseflow-venv/bin/python desktop/test/personal-model-test.py

PAIN_AUDIT_DATA=/path/to/private-copy \
PLAYWRIGHT_MODULE=/path/to/playwright \
node desktop/test/personal-browser.cjs
```

Машиночитаемые значения: [personal-recommendations-evaluation.json](personal-recommendations-evaluation.json). Данные об отдельных треках и личная история в этот отчёт не включены.
