# Совместное прослушивание

На главной внизу: **На одной волне → Слушать вместе**. Создайте комнату, выберите ведущего с предложениями или равные права, скопируйте приглашение и передайте другу. Участник вставляет приглашение в том же окне. В приглашении уже есть адрес сервера и, при необходимости, отпечаток сертификата.

Ведущий принимает предложения, меняет порядок, запускает песни, управляет паузой и перемоткой. В режиме равных прав управление доступно обоим. Обычные Play, Next, Previous и перемотка в этом режиме управляют общей комнатой. Щелчок по своей песне добавляет её в очередь либо в предложения. Закрытие окна не отключает комнату; **Выйти** завершает участие. Выход ведущего закрывает комнату. При потере соединения проигрывание приостанавливается; переподключение сохраняет личность и права ведущего.

Сервер и имя меняются также в настройках приложения. Используется отдельный режим, обычные рекомендации не перестраиваются и не участвуют в общей очереди. После выхода восстанавливается прежний локальный контекст на паузе.

## Музыка и синхронизация

Сначала приложение ищет точное локальное совпадение записи по названию, исполнителю, длительности и размеру. Другие версии не подставляются. Если совпадения нет, файл транслируется от участника, добавившего его. Его приложение должно оставаться открытым; если файл находится на телефоне, телефон должен быть доступен его приложению.

VPS соединяет два HTTP-потока с поддержкой Range и обратного давления Node.js. Ни музыка, ни библиотека, ни история на нём не сохраняются. Для записи на диске есть только сам сервис, сертификат и ограниченные журналы запуска. При отмене чтения поток источника закрывается. Отдельный запрос не может читать произвольный путь: передающая сторона обслуживает только ID треков, которые она сама предложила в этой комнате.

Общий сервер задаёт очередь, состояние и момент начала воспроизведения. Клиенты сверяют часы по середине сетевого RTT и корректируют расхождение позиции больше 250 мс. Небольшие расхождения внутри точности браузерного медиатаймера не вызывают постоянных перемоток. Это совместное прослушивание через отдельные декодеры, а не студийная синхронизация с точностью до сэмпла. Скорость буферизации зависит от соединений участников. В комнате локальные плавные переходы отключены, чтобы участники не перескакивали на разные песни независимо друг от друга.

## Собственный сервер

Сервер совместим с Node.js 22 и опубликован вместе с приложением. Никакая учётная запись Pain не нужна. Доверенный сервер видит общую очередь, имена участников и передаваемое аудио; TLS защищает соединение до сервера. Сквозного шифрования аудио между участниками эта версия не заявляет. Приглашение даёт доступ к комнате: передавайте его только нужным людям.

Собрать из корня репозитория:

```sh
docker build -f relay/Dockerfile -t pain-listen .
```

Нужен свободный TCP-порт и HTTPS. Для собственного сертификата создайте отдельную папку `certs`, не переиспользуя настройки других сервисов:

```sh
mkdir certs
openssl req -x509 -newkey rsa:2048 -nodes -days 365 \
  -keyout certs/key.pem -out certs/cert.pem -subj '/CN=Pain listening relay'
sudo chown 1000:1000 certs/key.pem
chmod 400 certs/key.pem
chmod 444 certs/cert.pem
```

Пример запуска на Linux с отдельным свободным портом 8448. Сеть host позволяет обойтись без изменений Docker NAT; проверьте, что этот порт не занят вашим VPN или другим сервисом:

```sh
docker run -d --name pain-listen --restart unless-stopped \
  --network host --memory 128m --memory-swap 128m --cpus .35 --pids-limit 64 \
  --read-only --cap-drop ALL --security-opt no-new-privileges \
  --tmpfs /tmp:rw,noexec,nosuid,size=8m \
  --log-opt max-size=1m --log-opt max-file=2 \
  -v "$PWD/certs:/certs:ro" \
  -e TLS_CERT=/certs/cert.pem -e TLS_KEY=/certs/key.pem -e PORT=8448 pain-listen
```

В приложении укажите `https://ваш-сервер:8448` и SHA-256, полученный командой:

```sh
openssl x509 -in certs/cert.pem -noout -fingerprint -sha256
```

При публичном доверенном сертификате отпечаток можно не указывать. При собственном сертификате приложение проверяет точное совпадение до отправки ключей комнаты. После замены сертификата обновите отпечаток и создайте новое приглашение. HTTP разрешён только на localhost для разработки. Не пересылайте SSH-пароль через приглашения: для работы комнат он не нужен.

По умолчанию ограничены 32 комнаты, 96 WebSocket-подключений, 8 участников в комнате, 100 записей очереди с предложениями и 64 передачи. Каждому участнику разрешены не более четырёх одновременных передач. Неиспользуемые комнаты удаляются через 30 минут; текстовые сообщения ограничены 32 КиБ, сжатие отключено. Ограничения ресурсов служат защите слабого VPS, не являются параметрами рекомендателя.
